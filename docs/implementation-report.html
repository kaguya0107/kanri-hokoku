01概要

概要書に記載された画面は、すべて動作しています

協力会社の現場担当者がタブレットで使う「ユーザーサイト」、事務局が使う「管理者サイト」の双方を構築し、報告書の作成から提出、社内用報告書の作成、完了までの一連の流れが通しで動作する状態です。

02現場画面

タブレットでの入力（幅768px）

ご指定のとおり幅768pxで設計し、指で操作する前提でボタンを大きく取っています。画面上部には概要書と同じ手順表示（［1 基本情報］…［5 確認・署名］）を置き、いま何を入力しているかが常に分かるようにしました。

ご提案

パスワードのロックは15分で自動解除する方式としました。概要書では「3回エラーでロック、解除は事務局」となっておりましたが、IDが会社単位のため、お一人の打ち間違いで現場全員がログインできなくなります。休日・夜間の作業を考慮し、15分で自動的に解除される方式に加え、管理画面からの即時解除もご用意しています。

03部品選択

交換部品 1万件からの選択

実際に1万件を登録した状態で動作しています。検索と50音での絞り込みに対応し、応答は1000分の1秒台です。件数が増えても速度は落ちません。

ご確認のお願い

50音での並べ替えには、部品マスタへの「読み仮名」列の追加が必要です。漢字表記からは読みを機械的に判定できないためです。現在はデモ用の読みを登録して動作させております。1万件への読み付与について、ご相談させてください。

工夫した点

検索して絞り込むと、すでに数量を入力した品目が画面から消えてしまいます。これを避けるため、選択済みの部品は検索結果とは別に、常に画面上部へ固定表示する構成としました。

04点検入力

測定値の入力と、作業完了の確認

  • 測定値の行数を可変にしました。画面例では5行でしたが、部屋数が5を超える現場に対応するためです。
  • 手書きサインは実際に動作します。指・スタイラスペンの両方に対応し、署名中に画面がスクロールしないようにしています。上の画面に表示されている署名は、実際に入力したものです。
  • 確認事項の文言は管理画面から変更できます。概要書では3〜5の文言が未定でしたので、後から変更できる方式にしております。
ご提案

入力内容は画面ごとに保存しています。概要書では最後の「つぎへ」で全体を登録する記載でしたが、その方式では作業の途中で通信が切れた際に、それまでの入力がすべて失われます。各画面で保存し、最終画面では提出済への切り替えのみを行う構成としました。

05帳票

報告書PDFの出力

入力された内容から、下記のPDFを作成します。画面でのプレビュー、印刷、メール添付に対応しています。

重要なご相談

帳票はExcelを変換するのではなく、同じ体裁をシステム側で組み直して出力しています。ご指定のさくらインターネット「ビジネス」では、ExcelをPDFへ変換する仕組みを動かすことができないためです。現在の出力は上図のとおりですが、お手元の様式と細部で異なる箇所がございましたら、ご指摘いただければ調整いたします。正式なExcelテンプレートをご提供いただけますと、より正確に合わせ込めます。

06一覧・社内用

報告書の一覧と社内用報告書

  • 一覧に絞り込みと「複製」を追加しました。件数が増えたときに目的の報告書へたどり着けるようにするためです。複製は同じ病院での再点検を想定した機能で、署名・PDF・メール履歴は引き継ぎません。
  • 移動・作業時間に日付を持たせました。複数日にわたる作業や、22時から翌1時までのように日付をまたぐ作業を記録できるようにするためです。上図では2日分を入力し、移動7時間30分・作業20時間10分が自動計算されています。
  • 状態を4区分にしました。下書き／提出済／社内用作成済／完了（請求済）です。概要書の「完／－」の2区分では、業務の流れの途中経過を表せないためです。
07管理者

管理者サイト（幅1600px）

事務局のパソコンからご利用いただく画面です。全協力会社の報告書を横断して確認できます。

ご提案

アカウント登録画面に、初期パスワードの発行・ロック解除・利用停止を追加しました。概要書の登録画面にはパスワードの項目がなく、発行方法が定まっていなかったためです。パスワードは暗号化して保存しますので、管理者様でも後から内容を確認することはできません。お忘れの場合は再発行していただく運用になります。

ご提案

マスタの取込は「内容を確認してから確定する」方式に変更しました。概要書では「書き込む前にDBをクリア」となっておりましたが、1万件の取込中に処理が中断すると、マスタが空のまま失われる恐れがあります。取込前に追加・更新・無効化の件数とエラー行をご確認いただき、そのうえで確定する手順としました。また、取込データに含まれない品目は削除せず「無効」として残すため、過去の報告書の記載内容が変わることはありません。

最も重要なご相談

通信環境への対応をどこまで行うかによって、開発規模が大きく変わります。概要書では「開発時に詳細を検討」とされておりましたが、次の3段階のいずれをご希望かによって費用が大きく異なるため、着手前にお決めいただきたく存じます。

段階できることできないこと
段階1 画面を移動しても入力内容が消えない
※現在この段階まで実装済みです		 通信が切れている間の新規入力・保存
段階2 圏外でも報告書の入力・保存を継続し、電波が戻ると自動送信。部品などのマスタも端末に保持 PDF作成・メール送信・過去分の閲覧は通信時のみ
段階3 過去の報告書の閲覧やPDFの作成まで、すべて端末内で完結 —

概要書の第8章の記載内容からは段階2が想定されていると読み取れます。段階2でよろしければ、次のフェーズとして着手いたします。
